# 哈鏌本機 AI 伺服器（POC）

把一台有 NVIDIA 顯示卡的電腦變成 App 的 AI 主機。全部使用免費的開源模型，錄音和資料不會離開這台電腦。

| 功能 | 使用的模型或工具 |
|---|---|
| 語音轉文字 | MediaTek **Breeze ASR 25**（台灣華語加英文）。想試台語可改用 Breeze ASR 26 |
| 分辨說話者（選配） | pyannote speaker-diarization 3.1 |
| 檔案轉文字 | PDF、Word、Excel、PowerPoint、純文字，用程式直接讀取 |
| 照片辨識（選配） | Ollama 視覺模型，例如 `qwen2.5vl:7b` |
| 整合分析 | Ollama 語言模型，預設 `qwen2.5:7b` |

所有工作會排隊依序執行，8GB 顯示卡（例如 RTX 4060 筆電版）也跑得動。語音模型和語言模型會輪流使用顯示卡。

---

## 一、安裝（只要做一次）

**需要**
- Windows 10 或 11
- NVIDIA 顯示卡，並已更新到最新驅動程式
- 約 20GB 的硬碟空間
- 可以連上網路（第一次安裝要下載模型）

**步驟**
1. 把整個 `local-ai-server` 資料夾複製到電腦，例如 `D:\himore-ai`。
2. 用記事本打開 `config.bat`，把 `API_KEY` 改成你自己的密碼。
3. 雙擊執行 `install.bat`。安裝程式會自動處理：
   - Python 3.11、PyTorch（CUDA 版），以及其他需要的套件
   - 下載語音模型（約 3GB）
   - 安裝 Ollama，並下載語言模型（約 5GB）
   - 安裝 Cloudflare Tunnel

   全部大約需要 20 到 40 分鐘，視網路速度而定。
4. 安裝過程中，畫面會顯示「CUDA 可用：True」以及顯示卡型號。如果顯示 False，請先更新 NVIDIA 驅動程式，再執行一次 `install.bat`。

## 二、每次使用

1. 雙擊 `start.bat` 啟動 AI 伺服器，這個視窗不要關。
2. 雙擊 `tunnel.bat`，畫面上會出現一行網址：
   ```
   https://xxxx-xxxx.trycloudflare.com
   ```
3. 在 App 填入設定：
   - 業務手機：「我的 → AI 伺服器」
   - 後台：「系統設定 → AI 服務與帳號」

   填入上一步的網址，以及 `config.bat` 裡的 `API_KEY`。先按「測試連線」，看到「已連線」後再按「儲存」。
4. 照平常一樣記錄拜訪，送出後就會由這台電腦轉文字和分析。

> **注意**
> - `tunnel.bat` 產生的是臨時網址，**每次重新執行都會變**，App 要重新填一次。想要固定網址，可以申請免費的 Cloudflare 帳號，改用正式通道。
> - 示範和測試期間，電腦不能進入睡眠，`start.bat` 和 `tunnel.bat` 兩個視窗都要開著。
> - 透過通道上傳的單一檔案上限約 100MB。一小時的錄音約 60MB，在範圍內。

### 先確認連線（不載入模型）

安裝前或還在安裝時，可以先執行 `test-fake.bat`。它會用示範模式啟動伺服器，不會真的轉寫或分析，只回傳固定的示範結果，可以先確認 App 和通道連得上。

## 三、調整設定（config.bat）

| 設定 | 說明 |
|---|---|
| `API_KEY` | App 連線用的金鑰。務必修改，否則知道網址的人都能使用 |
| `ASR_MODEL` | 語音模型。台灣華語用 `MediaTek-Research/Breeze-ASR-25`；想試台語改成 `MediaTek-Research/Breeze-ASR-26` |
| `LLM_MODEL` | 分析模型（Ollama 的模型名稱）。8GB 顯示卡建議 7B 到 8B 等級，例如 `qwen2.5:7b`。換模型後要先執行 `ollama pull 模型名稱` |
| `VISION_MODEL` | 照片辨識模型，留空就不辨識照片。例如 `qwen2.5vl:7b`，使用前要先 `ollama pull` |
| `HF_TOKEN` | 分辨說話者用，見下一節 |
| `LLM_CTX` | 分析模型一次能讀的長度。8GB 顯示卡維持 16384 即可，長錄音靠分段處理 |
| `CHUNK_CHARS` | 逐字稿超過這個字數就分段整理再彙整，預設 6000 |
| `ASR_WINDOW_MIN` | 長錄音每幾分鐘切一段轉寫，用來回報進度，預設 10 |

改完設定後，關掉 `start.bat` 再重新開啟。

## 四、長時間錄音（一小時以上）

App 和伺服器都已經針對長錄音處理：

| 環節 | 做法 |
|---|---|
| 錄音檔大小 | App 用語音專用格式錄音（單聲道、48kbps），一小時約 21MB。通道單檔上限約 100MB，約可錄 4 小時以上 |
| 錄音不中斷 | 螢幕鎖定或切換到其他 App 時會繼續錄（APK 版），通知列會顯示錄音中 |
| 語音轉文字 | 每 10 分鐘切一段依序轉寫，切點選在最安靜的地方，避免切斷句子。處理中頁面會顯示「語音轉文字 3/6」 |
| 分析 | 逐字稿太長時，先分段整理，再彙整成一份紀錄，避免超過分析模型能讀的長度。如果直接整段丟進去，模型會**默默丟掉前面的內容**。業務補充的更正在彙整時一樣優先 |
| 等待時間 | App 最多等 3 小時，可以離開處理中頁面，完成後會通知 |

**處理時間要實測**：顯示卡等級、錄音長度和對話密度都會影響。建議先用一段 30 分鐘的錄音記下轉寫和分析各花多久，再推估長錄音需要的時間。

## 五、啟用「分辨說話者」（選配）

1. 到 https://huggingface.co 註冊帳號。
2. 打開以下兩個頁面，各按一次同意使用條款：
   - https://huggingface.co/pyannote/speaker-diarization-3.1
   - https://huggingface.co/pyannote/segmentation-3.0
3. 在 Settings → Access Tokens 建立一個 Read 權限的 token。
4. 把 token 填進 `config.bat` 的 `HF_TOKEN`，再執行一次 `install.bat`。

啟用後，逐字稿會標示「語者A」「語者B」。

## 六、常見問題

| 狀況 | 處理方式 |
|---|---|
| App 顯示「連不到 AI 伺服器」 | 確認 `start.bat` 和 `tunnel.bat` 都開著，且網址是這次 `tunnel.bat` 顯示的新網址 |
| App 顯示「API 金鑰不正確」 | App 填的金鑰要和 `config.bat` 的 `API_KEY` 完全相同 |
| 「Ollama 找不到模型」 | 在命令提示字元執行 `ollama pull qwen2.5:7b`（或你設定的模型名稱） |
| 第一次轉寫很慢 | 第一次要把模型載入顯示卡，之後會比較快 |
| 顯示記憶體不足（CUDA out of memory） | 關掉其他使用顯示卡的程式；或把 `LLM_CTX` 調小到 8192；或換更小的分析模型 |
| 簡體字 | 伺服器會自動轉成繁體 |

## 七、資料與安全

- 錄音、照片和檔案只會在處理時暫存在這台電腦的記憶體裡，伺服器不會另外存檔。
- Breeze ASR 25 和 26 都採 Apache 2.0 授權，可以商用。其他模型請依各自的授權條款使用。
- 這是 POC 用的架構。正式上線時，應改成公司內部的伺服器，並加上固定網址、帳號權限和使用紀錄。
